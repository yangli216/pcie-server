# 门诊病历模板字段维护与生成设计

**适用于白云分支。** 管理端按模板版本维护原始字段、书写规则及回写映射。桌面端通过签名快照 v2 读取有效规则。旧设备的 v1 兼容边界见设备协议。[服务端需求](../PRD.md#病历模板管理统一口径) · [设备与管理接口设计](../API.md#outpatient-field-policy)

## 1. 管理员维护的对象

管理员打开“病历模板 → 门诊病例模板”，在本人的机构权限内按模板名称或 ID、模板对 hash 和状态定位版本。保留模拟病例预渲染和只读解析详情。列表提供“字段维护”、启用、停用及逻辑删除，显示版本状态、更新时间。始终展示 HIS 模板 ID 和版本，以便区分同名模板及直接使用 ID 作为名称的模板。两侧复用住院已有的生成类型选择、提示词来源和草稿审核交互。

| 字段维护页 | 需要展示和支持的操作 |
| --- | --- |
| 原始字段与临床含义 | 展示原始字段 ID、定义名、渲染名或源章节、字段类型、只读属性、字典和所在原句。查看默认含义，可按本版本维护含义。例如同属“主诉”的“症状名称”与“持续时间”各有自己的含义。运行时名称有差异时保留各方原值。 |
| 回写映射 | 展示自动来源、人工覆盖、当前标准段和直接写入／章节组合。继续支持明确不映射及恢复自动映射。未映射的可写自定义栏仍能按原始 ID 返回。 |
| 生成类型 | 显示默认判定、人工选择、实际生效的 AI 或人工／HIS 及原因。维护项为“使用默认、AI、人工／HIS”。受保护或只读栏显示限制原因。可按生成类型、提示词来源独立筛选。 |
| 正文规则 | 并列展示默认规则、当前生效提示词及其来源。管理员可填写附加正文约束，按字段信息生成草稿、编辑、保存、恢复默认。列表支持按字段 ID、含义或提示词搜索，以及已维护、默认待维护、非 AI 筛选。 |

版本字段表每行显示“原始字段／章节、含义、可写属性、有效映射、生成类型、生效提示词摘要、维护”。点击“维护”后固定显示原始字段和所在章节。默认打开“书写规则”，依次呈现生成类型、当前生效提示词、附加正文约束、生成草稿、可编辑正文和保存按钮。“回写映射”页签保留现有自动来源、标准段和投影维护。两个页签分别保存，编辑其中一项不会改动另一项。生成类型为人工时，提示词区解释该栏由人工或 HIS 填写。

“有效映射”只统计有标准段去向的字段。“AI 字段数”统计该版本配置允许 AI 写的字段。“本次生成数”由医生端按实际返回值统计。三者各自显示分母。模拟预渲染展示控件、映射和规则效果，示例值标注为合成数据。

回写映射的合成预览同时列出原句中的各栏、固定文字，以及当前选定标准段在 SDK 中的回参。调整映射时，模板正文仍由完整原句渲染。选择明确不映射时提示该栏仅返回原始字段，多栏投向同一标准段且无法组合时提示冲突字段。

## 2. 判定每个字段由谁写

按以下顺序得到模型可以输出的字段。可参考的病例资料单独处理。

1. **HIS 确定本次写入上限。** 原始 ID 必须在本次 `targetFieldIds` 内，控件可见、可写、可唯一配对。隐藏项、动作、只读项及身份、就诊时间、签名等系统专属项不接受 AI 值。管理员不能扩展 HIS 授权。
2. **模板版本决定是否使用字段生成。** 仅启用版本生成模板字段。停用、逻辑删除或没有 AI 目标时，配对成功的表单仍可供医生按现有权限核对和编辑。语音首轮继续生成原有问诊内容。
3. **管理员保存的生成类型优先。** 同一字段的显式“人工／HIS”持续生效，重新解析和重新登记均不得打开。显式“AI”仍受前两项限制。“使用默认”读取原结构定义中明确提供的 `AI_SUITABLE`。缺少该属性的旧模板沿用原有临床字段类别和 HIS 本次白名单，保留未识别但合法的自定义临床栏。历史解析快照可能把缺省记成 `aiSuitable=false`，须从保存的定义按章节与字段身份辨认“未提供”。局部无法匹配时保留原始资料与其余可判定字段，标明该栏待核对。
4. **映射独立于生成类型。** 选择“不映射”只取消标准段投影。选择“人工／HIS”允许保留、核对和按既有授权返回 HIS 或医生的原值。语音首轮、兼容的整段正文、章节补丁和重试共用本轮可生成字段范围。人工栏保留 HIS 原值和医生直接编辑的值。

已授权的就诊资料、已选诊断与医嘱、医生修订、可用的只读或非目标临床原文、模板固定句式及单位，按来源提供给模型。字段依赖描述使用线索，不能用作删减资料的白名单。缺项保留其余内容，异常数值保留原值，解析有差错时保留可用原文，冲突资料同时呈现并注明出处。沿用现有身份脱敏与隐藏控件边界。

## 3. 正文规则的编制与生效

服务端以同一个确定性规则生成器为管理端预览和设备生成字段指令。默认规则以现有门诊临床类别、值形态和缺省草稿约定为基线，结合模板名称、原章节、字段 ID 和含义、相邻槽位、固定单位、字典及来源要求。持久配置中只使用模板结构和管理员填写的书写要求，实例中的当前值、患者身份和就诊原文不得拼成供其他就诊复用的规则。共用分类规则随 `ruleSetVersion` 版本化。机构差异存成字段配置，源码中不按机构或字段 ID 写特例。

| 生效组成 | 取值规则 |
| --- | --- |
| 字段正文 | 默认按字段职责生成。保存的自定义正文替代默认的内容要求，保留字段身份、已维护含义和本次可用资料。 |
| 附加正文约束 | 独立保存，逐字作为该栏的补充要求加入一次。例如“只填写症状名称，持续时间填在相邻栏”。 |
| 值格式和事实边界 | 数值槽只填有依据的数值，模板负责固定单位。单独的单位槽按模板或合法字典填写。整段文本可保留单位。字典只接受现有选项，缺少依据按现行空值／未提及默认规则处理。字段规则只约束本字段正文，外层 JSON 或语音事件、写入范围和事实来源由运行时保证。 |

默认编制时先看源原句与控件位置。等价全文栏承载完整叙述；拆栏分别描述各自的小项；时长旁已有固定单位时，时长槽只收数量。通用的“主诉含症状和时长”适用于整章，拆栏规则应明确每栏分担哪一部分。同名章节按源章节 ID 分开，标准段映射相同也不合并其字段规则。

同一句中相邻的主症状和持续时间两栏都有值时，按模板顺序呈现，例如“咳嗽3天”。单独返回的原始控件仍各自携带文本，SDK 章节组合继续使用有字段名的标准段。

规则库 v6 采用萧山门诊的事实与书写口径。先用医生本轮修订和已确认事实，缺项可回看原始问诊或转写。普通主诉写症状和有依据的时长，仅在明确的慢病复诊配药场景使用本次已选病种。时间数量、相邻单位、伴随症状各写各栏。带字典的时间栏按选项显示的含义填写，例如“初始／全程／始末”表示阶段，编码不能当作时长数值。只有明确询问或检查的阴性结果可写为事实。原始字段名与原句所指不一致时保留两处原文，具体所指未经医生核实则返回空字符串。预置、候选和未提及默认继续按原来源展示。检查结果、正式诊断、已选医嘱和随访安排分别按来源填写；医生修订和回写不触发新草稿的默认复诊逻辑。

“生成草稿”只确定性拼装可编辑的正文草稿，同时展示合并附加约束与值格式后的预览。生成和取消均不保存。保存操作一次提交生成类型、含义、附加约束、自定义正文，并返回重新计算的生效规则。编辑区保存可编辑正文，预览区只读，避免重复拼接。界面直接邀请管理员填写正文要求，“生成一个提示词”等草稿操作说明不进入默认正文任务。恢复默认提示词清除自定义正文和附加约束，保留含义、生成类型和映射；恢复默认含义、恢复默认生成类型、恢复自动映射均为各自独立的操作。切换人工时保留已维护文字供再次启用，设备只收到非 AI 结果。

## 4. 版本、保存与生命周期

不可变快照仍以认证机构、`templateId` 和两份解码原文的 `templateHash` 为身份。字段使用原始 `fieldId`，章节 ID 用于核对。既有映射继续使用独立映射表。新增的版本状态和单调递增的 `revision` 按 `idSnapshot` 存储，字段维护按 `idSnapshot + fieldId` 唯一存储。策略状态、修订号以及按原始字段 ID 索引的维护值存于同一快照行；以版本行锁串行化映射和规则更新。解析原文与自动解析 JSON 仍独立保存。记录操作者和更新时间，沿用管理端权限、机构校验及操作审计。规则存储只含模板配置，患者资料、实际生成正文及医生修订留在原业务链路。无新增环境变量。

| 版本状态 | 管理和设备行为 |
| --- | --- |
| 首次／启用 | 首次从启用、修订号 0、字段继承默认开始。已有快照可按此逻辑读取，无需批量改写。已有人工映射继续生效。 |
| 停用 | 保留配置和快照，新一轮生成返回停用状态。显式启用恢复保存的字段规则及人工关闭项。 |
| 逻辑删除 | 从默认列表移除，可按状态查询历史。保留版本标记、规则和解析证据；同一模板对再次登记仍命中删除状态，不能靠重新上报复活。删除状态仅供追溯。 |
| 模板对换版 | 任一解码原文变化即形成新 hash，即使只改变了渲染值，也不能复用上一版本人工覆盖。页面展示同 ID 的版本和各自维护状态，管理员在目标版本核对并保存。 |

字段保存、恢复、映射变化和模板状态变化在同一版本上原子递增修订号。管理端提交读取时的 `expectedRevision`，过时写入返回冲突并保留未保存草稿供比对。重复设置相同内容无需递增；网络重试先读回，目标值已达成即视为成功。并发首次登记以既有快照唯一键收敛。设备在同一一致性视图读取有效映射、字段规则、状态和修订号。规则的身份同时包含 `ruleSetVersion`，支持识别默认规则库升级。

## 5. 桌面端三个生成入口

| 入口 | 生成与回写 |
| --- | --- |
| 独立门诊分析 | 命中或首次登记后读取此次有效规则。将字段 ID、含义、生效规则、原句、相邻槽位、固定文字和单位连同本次病例资料交给现有一次分析请求。无 AI 目标时直接进入可核对的草稿。 |
| 绑定门诊模板的语音首轮 | 同一份字段任务加入原语音首轮流。按源章节 ID 组织，接收原始字段 ID 的值，依据模板原句组成正文。完整的问诊病历、已选诊疗内容和语音事件继续使用原协议，每个字段只执行一次规则。 |
| 医生补充、重试或单章修订 | 发起新模型调用前重新解析有效配置。单章只输出该章仍获准的字段，保留医生最新正文、修订来源及显式清空。医生正在修改或已确认的草稿不被迟到结果覆盖。 |

同一轮固定就诊、请求、模板 ID、hash、目标 ID、修订号和规则库版本。编辑、选择回写、等待回执使用医生正在核对的草稿。新一轮发现配置变化时重建字段任务，旧 AI 值不能充当新结果，保留医生原文和结构化来源。会话恢复保留历史草稿身份，重新请求时再核对策略；相同模板 hash 不足以判定可复用一次 AI 结果。

桌面端仍由门诊统一提示词组装入口将服务端正文规则与本次资料拼入相应请求。规则属于可信配置，原句、模板预置和病例属于带来源的资料。独立分析、语音首轮和医生补充使用相同的原句描述与字段规则。补充可引用只读或非目标临床栏的原始资料和医生修订，输出范围仍按当次版本。不把资料里的文字提升为操作指令。已确认的结构化事实与医生编辑沿用原有优先级，兼容标准段及 `emrFieldValues` 的投影也遵守本轮来源和选择范围。

## 6. 医生看到的结果与验收

独立页和语音模板区域分别显示本次可由 AI 填写的目标数、实际采纳的 AI 非空字段数，以及人工／HIS 已填、模板预置、未提及默认和待补充来源。“AI 已填”按本轮模型确实返回、通过该栏类型／字典校验、最终仍采用的原始字段 ID 去重。缺键、空值、无法匹配的字典、预置、默认、医生旧稿或被结构化结果取代的 AI 值均不计入。与模板文字相同的值仅在本轮有模型确认且仍作为病例草稿采用时计入。临床事实准确性由医生核对，界面计数无需另调模型评判。

有部分正文就呈现实际草稿和剩余空栏。有 AI 目标、本轮返回全空且缺少病例正文时显示“待补充”；若相关栏都已有 HIS 或医生正文，则显示“已保留原有内容，AI 本轮未新增”。本来就没有 AI 目标时显示“本次无 AI 生成字段”。请求或流失败单独说明并保留已到达的可核对内容。由医生决定编辑、补充、确认及选择回写，沿用现有 HIS 单次回执。模板对身份错误仍沿用现有错误处理。

同一份合成资料“咳嗽3天”应在全文主诉栏得到“咳嗽3天”，在拆栏模板分别得到“咳嗽”和“3天”；若时长旁已印“天”，数值栏得到“3”。对照后台保存前后的真实字段任务、模型响应、页面正文和最终回参，可以区分规则错误、模型遗漏和投影错误。跨仓验收用例与证据边界见[验证策略](../../TESTING_STRATEGY.md#outpatient-field-policy-acceptance)。合成用例与真实临床质量分开验收。模板中已印“天”时，页面正文为“咳嗽3天”，原始字段回参为“咳嗽”和“3”。本地 SDK 的章节组合标准段按顺序接收“症状名称：咳嗽；持续时间：3”。真实 AI 成对对照、医生质量评价和现场 HIS 落库另行留证。
