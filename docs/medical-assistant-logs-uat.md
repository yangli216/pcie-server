# 医学助手日志：实现与验收

验收日期：2026-10-20（America/Los_Angeles）。

## 可行性与范围

用户确认记录独立“医学助手”对话，不包含语音问诊、慢病配药或其他问诊日志。原型中的模拟诊断和机构数据仅用于理解交互，不导入业务库。

现有 `/v1/ai/chat` 服务端审计已经保存输入消息与回答，且有来源模块、场景、机构和时间索引，因此可直接复用 `c_ai_op_log`，无需新增表、执行 SQL 迁移或引入依赖。

后台新增“医学助手日志”菜单，页面路径 `/admin/#/medical-assistant-logs`。支持本日、本周、本月、本季度、本年度、自定义日期，医生姓名和机构筛选，10/20/50/100 条分页，完整提问 CSV 导出，以及医生输入/AI 输出左右对照详情。窄屏详情自动改为单列。

一次服务端代理请求对应一条日志，包括失败和重试请求；它不等同于功能统计中的一次用户操作。仅展示最后一条 user 消息与本次回答，避免重复展示多轮历史上下文。图片只显示数量，AI 回答按文本显示。

## 服务端与客户端配套

- 服务端：`modules/assistantlog` 提供受 `AdminAuthFilter` 保护的列表、机构选项、详情和 CSV 接口。所有读取限制到 `ai_proxy + ai + chat_panel + chat-stream/chat`，避免通过详情 ID 读取其他业务日志。
- 桌面端：`floating-ball/src/services/llm.ts` 在现有签名请求内携带 SDK 握手上下文的医生 ID、姓名和 HIS 机构快照。只为 `chat_panel` 增加元数据，不传给上游模型，不改变请求签名和功能统计。
- 旧客户端可以继续使用；历史缺少医生快照的日志显示“未记录”，无法可靠回补。要让新日志带上医生姓名，需要部署本次桌面端改动并完成 SDK 握手。
- 后台机构由设备鉴权确定；上报的人员字段仅是审计快照，不能用作授权凭据。统计专用账号禁止访问临床全文日志。
- CSV 为 UTF-8 BOM，保留多行与引号，保护公式字符。一次最多 1000 条，超限明确拒绝；事务内游标逐条读取含图片的审计载荷。
